## 2. Hybrid Branch Strategy and Concrete Layouts

**Deciding rule (`computed`):**
1. **Upstream-tracking / fork defaults:** Preserve fork default branches untouched whenever they track a newer release or upstream branch; reserve bare release names (`lineage-*`, `cm-*`, `twrp-*`, `main`) for upstream or already-converged release lines.
2. **Single device on a release (or conflict-free multi-device release):** Maintain the per-device integration branch (`dev/<device>/<track>`); where multiple devices share a conflict-free release, keep one shared synthesis branch (`synth/<track>` or the existing converged release branch) plus exact pinned SHAs in the ledger.
3. **Conflicting multi-device release (`merge-tree` fails):** Keep separate per-device branches (`dev/<device>/<track>`) for deterministic rebuilds and create an explicit reviewed `synth/<track>` synthesis branch that preserves both intents (Owner ruling 3).
4. **Unmerged local branches and open PRs:** Preserve open PR heads in place; push every unpushed local branch that is not an ancestor (and not patch-id-superseded) of a remote branch under `topic/<device>/<track>/<slug>`.

## 3. Collision-Free, Upstream-Sync-Stable Naming Scheme (`proved` collision-free across all 25 forks)
- Reserve bare upstream names (`lineage-*`, `cm-*`, `android-*`, `twrp-*`, `main`, `master`, `stable`, `stable/*`, `shipping/*`, `staging/*`, `caf/*`) strictly for upstream mirrors and existing fork defaults.
- Place all owner-managed branches under four dedicated top-level namespaces proved absent from all 25 public owner forks (`ls-remote` hits = 0):
  - **Device integration:** `dev/<device>/<upstream-track>` (e.g., `dev/tuna/lineage-18.1`, `dev/a11/lineage-19.1`, `dev/a11/lineage-22.2`, `dev/m8/lineage-22.2`, `dev/m8/twrp-14.1`, `dev/a11chl/twrp-11`, `dev/twrp-generic/twrp-12.1`). Encoding `<upstream-track>` decouples device identity from upstream merges/rebases and prevents collisions when porting to a newer track (`dev/<device>/<new-track>`).
  - **Multi-device synthesis:** `synth/<upstream-track>` (e.g., `synth/lineage-19.1`). Reconciles upstream `<upstream-track>` merges cleanly without mutating bare upstream branch names.
  - **Unmerged topic work:** `topic/<device>/<upstream-track>/<mechanism-slug>` (no session dates, no tool/actor prefixes required).
  - **Triaged dirty-tree capture:** `wip/<device>/<upstream-track>/<mechanism-slug>` (only after hygiene/size triage; dates live in commit messages).

## 4. Ledger Layout and Fail-Closed Verifier Defeating Fork-Network Leaks
- **Per-device directory (`devices/<device>/<track>/`):** `pinned.xml` (every `<project>` pins `remote`, `name`, `path`, `revision="<40-hex-sha>"`, `upstream="refs/heads/<branch>"` or `refs/tags/<tag>`), `local_manifests/*.xml` (exact copies including `a11.xml`, `m8.xml`, `bullhead.xml`, `tuna.xml`, `a11chl.xml`, `m8-v15.xml`), `repos.tsv` (`path`, `remote_url`, `upstream_url`, `ref`, `sha`, `owner_status`, `source_tree`), and `manifest-meta.tsv` (manifest URL, branch, SHA, local commit disposition).
- **Cross-repository matrix (`matrix/`):** `forks.tsv` (every owner fork, upstream parent, default branch, visibility, network match) and `shared-forks.tsv` (forks shared by >=2 devices/tracks, conflict counts, `synth/<track>` branch, open PRs).
- **Fail-closed verifier (`scripts/verify-pins.sh`, POSIX `sh`, `set -eu`):**
  1. Reject any pin whose `sha` is not 40 lowercase hex characters or whose `ref` fails `^refs/(heads|tags)/` (blocks `refs/pull/*` and `refs/changes/*`).
  2. Query `GIT_TERMINAL_PROMPT=0 git -c credential.helper= ls-remote --heads --tags "$remote_url" "$ref"`; fail if absent.
  3. Pass immediately if `ref_tip == sha`.
  4. Otherwise fetch **only `"$ref"`** (never bare `"$sha"`) into a fresh isolated scratch repo with `--filter=blob:none` (deepening/unshallowing that single ref) and require `git merge-base --is-ancestor "$sha" FETCH_HEAD`. Because bare `"$sha"` is never placed in the git `want` list, GitHub's shared fork-network object store cannot supply a fork-only object when querying upstream; `merge-base` fails closed.
  5. Calibrate in CI (`scripts/test-verify-pins.sh`): known-good (`Oichkatzelesfrettschen/android_frameworks_base`, `refs/heads/lineage-19.1`, `687ef4d0c6...` -> PASS), known-bad fork-leak (`LineageOS/android_frameworks_base`, `refs/heads/lineage-19.1`, `687ef4d0c6...` -> FAIL), and known-bad PR ref (`refs/pull/2/head` -> FAIL).
