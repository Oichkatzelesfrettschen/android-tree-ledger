# Brief: integration strategy for publishing nine retiring Android source trees to owner forks

Read first: ~/Projects/gororoba-workspace/AGENTS.md, then the sections "Branching" and "Synthesis over selection" of ~/.claude/docs/agent-reference.md. Work read-only: change no file except your report; never commit, push, fork, open or merge a pull request, or call an authenticated GitHub API; spawn no subagents. You may run `git ls-remote` against the public GitHub URLs named in the material, and `git clone --depth=1` or `git fetch` into a scratch directory outside this directory, each command under 3 minutes. Every finding names a file and line of the material, or a command with its output.

Material (this directory, docs/integration-strategy/material/, all paths tree-relative):
- trees.tsv: one row per tree with project counts by verdict, object-store reference, manifest state and local manifests.
- local-work.tsv: one row per ref (HEAD and each local branch) of every project whose verdict is CANDIDATE, with its fetch remote, the owner repository of the same name (fork parent, default branch, visibility), and whether GitHub holds the ref: a tip, contained in a named owner branch by the GitHub compare API, or not found in the branches checked.
- standalone.tsv: checkouts that sit beside the repo trees (kernels, donors, device repos).
- patchids.tsv: `git patch-id --stable` of every local commit; equal patch-ids mark the same change.
- manifests.txt: each tree's manifest checkout state and local manifests.
- open-prs.txt: three open pull requests on owner device repositories.

How the inventory was taken (status: computed): a POSIX sh script ran per project `git rev-parse HEAD`, `rev-list --count HEAD --branches --not --remotes --tags`, `status --porcelain --untracked-files=normal`, `for-each-ref --contains HEAD refs/remotes refs/tags` and `rev-parse --is-shallow-repository`. PRISTINE means no local commit, no change, no stash and HEAD contained in a remote-tracking ref or tag; a failed read is UNREADABLE. It reproduced the facts recorded before it ran: twrp-12.1 has 5 changed files in 2 projects and no local commit; tuna/lineage-19.1 bionic holds branch port/lineage-19.1-tuna 53c1f010ad; desire510-18.1 has 22 projects whose alternates point at a moved path, and all 22 read clean with the moved path substituted. Counts above 10,000 come from shallow clones without remote-tracking refs; local-work.tsv shows those HEADs as tips on the owner fork.

Owner rulings that bind the strategy (status: recorded decisions, not under review):
1. Retire m8/lineage-22.2, tuna/lineage-18.1, tuna/lineage-19.1, bullhead/lineage-22.2, desire510-18.1, desire510-19.1, the desire510 kernel, twrp/twrp-11, twrp/twrp-12.1 and twrp14-m8, only after every local item, branch and pull request is on GitHub and each tree can be recreated from GitHub alone. tb132fu/android17 stays.
2. Push local work to the owner's existing forks; where none exists, create a public owner fork, vendor blob repositories included. Keep a public ledger repository (this one) per device, per repository and across repositories.
3. A conflict between two lines of work is analyzed and resolved by synthesis that keeps both intents; picking one side is refused.
4. The goal is a hybrid, granular structure from which each tree can be synced and rebuilt, and which can later sync with upstream.

## Claims under review (each is a claim; justify or falsify it)

1. Candidate A: each fork gets one integration branch per tree, named `<device>/<tree>` (m8/lineage-22.2, tuna/lineage-18.1, tuna/lineage-19.1, a11/lineage-18.1, a11/lineage-19.1, bullhead/lineage-22.2, twrp-m8/twrp-14, twrp/twrp-11, twrp/twrp-12.1), pointing at the checked-out HEAD, and the pinned manifest names it; fork default branches stay untouched. Status: hypothesis. Support: local-work.tsv owner_default_branch column (lineage-23.2, lineage-24.0) is newer than every retiring tree. Falsifier: a fork that already holds a branch named exactly `tuna`, `m8`, `a11`, `bullhead` or `twrp` (git refuses `tuna/x` beside `tuna`), or a manifest consumer that cannot fetch a branch with a slash.
2. Pushing each local branch under its own name is safe. Status: hypothesis. Falsifier: local branch names that equal existing fork branches with different tips; tuna/lineage-18.1 projects carry a local branch named `lineage-18.1`, and local-work.tsv shows desire510-18.1 frameworks/base HEAD contained in the fork's `lineage-18.1` while tuna/lineage-18.1 frameworks/base `lineage-18.1` 082f204127 is not found there.
3. Two trees of one release that share a fork (tuna/lineage-18.1 and desire510-18.1 in android_frameworks_base; tuna/lineage-19.1 and desire510-19.1 in android_bionic, android_frameworks_base, android_frameworks_av) never conflict under per-device branches, and a shared release branch would need a synthesis merge. Status: hypothesis. Support: patchids.tsv shows equal patch-ids only within one project of one tree. Falsifier: a pair of commits from two trees that touch the same lines.
4. A shallow project pushes to its fork when the fork network already holds the shallow boundary commit; otherwise `git fetch --unshallow` of that project precedes one retry. Status: hypothesis. Falsifier: a push of a shallow clone into a GitHub fork network refused although the boundary commit is reachable there.
5. Projects whose upstream is android.googlesource.com and that hold local commits (tuna/lineage-18.1 system/apex; m8/lineage-22.2 external/strace; tuna/lineage-19.1 system/memory/libion) get a GitHub home by forking the aosp-mirror mirror of the same path. Status: hypothesis. Falsifier: the mirror lacks the project, lacks the release branch, or lacks the base commit of the local work.
6. A PRISTINE project is reproducible from its manifest remote at its pinned SHA. Status: hypothesis. Falsifier: a pinned SHA that its remote no longer serves (a force-pushed or deleted branch; googlesource serves only reachable commits), so pinning must name a ref as well as a SHA.
7. Retirement order: desire510-18.1 before tuna/lineage-18.1 (625 projects borrow tuna objects); m8/lineage-22.2 keeps .repo/project-objects and .repo/manifests.git while tb132fu/android17 borrows from them. Status: measured (alternates census) for the dependencies; hypothesis for the order being sufficient. Falsifier: another tree, toolchain symlink or worktree that resolves into a retired tree.
8. Uncommitted changes (twrp-11: 5 files, twrp-12.1: 5 files, untracked prebuilts/clang files in five trees, desire510-18.1 android and art untracked files, twrp14-m8 manifest file m8-v15.xml, tuna/android_hardware_ti_omap4 and toolchains/ruuveal untracked files) are preserved as a commit on `<device>/<tree>-wip-20261124` in the matching fork.
